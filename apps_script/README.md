# Apps Script — SwitchBotの環境データ収集

SwitchBot APIから温度・湿度・CO₂濃度を取得し、Googleスプレッドシートへ記録するGoogle Apps Script（GAS）です。画面表示の仕様は[画面・データ仕様](../docs/SPEC.md)を参照してください。

## 構成

| ファイル | 役割 |
| --- | --- |
| `src/code.gs` | 記録処理 `recordEnvironment`、API取得・応答検証・リトライ |
| `src/util.gs` | Script Propertiesの読み取り・署名・リクエストヘッダー生成 |

2つの `.gs` ファイルは同一のGASプロジェクトへ配置します。GitHubの更新だけではGAS側のコードは更新されません。**既に時刻昇順になっているシートへの末尾追記を前提とします。**

## 1. Script Propertiesに認証情報を登録する（必須）

この版から、APIトークンなどをコードに埋め込む方式は使いません。GASエディタの **「プロジェクトの設定」→「スクリプト プロパティ」** に次の3項目を登録します。

| プロパティ名 | 値 |
| --- | --- |
| `SWITCHBOT_TOKEN` | SwitchBot APIトークン |
| `SWITCHBOT_SECRET` | APIシークレット |
| `SWITCHBOT_DEVICE_ID` | CO₂センサーのデバイスID |

- 名前は大文字を含めて完全一致させてください。未設定の場合、記録は失敗し、必要なプロパティ名をエラーログに出します。
- **本物のトークン・シークレット・デバイスIDをGitHubやフロントエンドへコミットしない**でください。
- Script Propertiesは同じスクリプトの編集権限を持つ人が参照できるため、スクリプトの共有範囲にも注意してください。

[SwitchBot公式のAPI仕様](https://github.com/OpenWonderLabs/SwitchBotAPI)で認証情報の取得方法やデバイス情報を確認できます。

## 2. スプレッドシートを準備する

スプレッドシートの「拡張機能 → Apps Script」で紐づいたスクリプトとして実行します（`SpreadsheetApp.getActiveSpreadsheet()`）。

- `log` シートが存在しなければ自動作成します。
- 1行目に `timestamp, temperature, humidity, co2` のヘッダーを作成します。
- データは**古い順（時刻昇順）**で、最新ログは**末尾**に `appendRow()` で追記します。
- 最大でデータ2016件＋ヘッダー1行を保持し、超えた場合は**2行目から古いデータを削除**します（5分間隔なら約1週間）。
- 記録時の並び順チェック・自動ソートは行いません。旧仕様（新しい順）のログを使う場合は、あらかじめA～D列を行単位で時刻昇順に並び替えてください。

| 列 | 内容 | 例 |
| --- | --- | --- |
| A | `timestamp` — UNIX秒 | `1739251200` |
| B | `temperature` — 温度（°C） | `24.5` |
| C | `humidity` — 湿度（%） | `55` |
| D | `co2` — CO₂濃度（ppm） | `800` |

## 3. GASコードを適用する

1. 稼働中のGASコードをバックアップします。シートは**時刻昇順への移行済み**であることを確認してください。
2. `apps_script/src/code.gs` と `apps_script/src/util.gs` を同じGASプロジェクトに反映します。認証情報は従来のScript Propertiesをそのまま利用します。
3. `recordEnvironment` を手動実行し、`log` シートの末尾に最新の計測値が追加されることを確認します。
4. 5分ごとのトリガーが1つだけ登録されていることを確認します。ブラウザで最新値とグラフの表示を確認します。

**旧ログの自動移行処理は削除済みです。** 新しい環境で旧方式のシートを流用する場合は、事前にバックアップを取り、A～D列をまとめてタイムスタンプ昇順に並べ替えてください。移行しないまま記録すると、2016件の上限超過時に削除対象を誤ります。

## 4. トリガー

エディタ左の「トリガー」で既存設定を確認します。未設定なら次のとおり追加します。

| 項目 | 設定値 |
| --- | --- |
| 実行する関数 | `recordEnvironment` |
| 実行するデプロイ | Head |
| イベントのソース | 時間主導型 |
| タイマーの種類 | 分ベース |
| 間隔 | 5分おき |

複数の同等トリガーが登録されていないかも確認してください。手動実行や重複トリガーによる同時書き込みは `LockService` で排他制御しますが、5分以内の複数実行を重複データとして自動判定・削除するものではありません。

## 5. エラー処理

- APIリクエストはHTTPステータスとAPIの `statusCode === 100` を検証します。
- HTTP 429・5xx、API内部エラー190、通信例外のみ最大**3試行**（初回＋再試行2回）します。待機は500ms・1000msです。HTTP 401などはリトライしません。
- APIレスポンスや数値が不正な場合、**シートに書き込まず失敗**します。実行履歴で原因を確認してください。
- API取得後、書き込み時のみScript Lockを取得し、末尾への追記・古いログの削除を行います。変更の `flush()` 後にロックを解放します。
- 失敗した定期実行分を後から埋め直す仕組みはありません。監視が必要ならGASの失敗通知を利用してください。

## 6. テストとWeb側との関係

`pnpm test` はNode.js上にGASのモックを用意し、正常系・認証不足・APIエラー・計測値欠損・競合・連続追記・保持件数を検証します。**実際のSwitchBotデバイスやGAS環境での動作保証ではありません。**

Web側の `src/sheetApi.ts` は、同じA～D列をgvizで読み込みます。Sheetの共有範囲を確認し、公開して問題ないデータのみを扱ってください。フロントエンドの更新・デプロイはGASのトリガー設定には影響しません。
